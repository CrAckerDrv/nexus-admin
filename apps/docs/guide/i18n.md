# 多语言（i18n）

内置一套**零依赖**的 i18n：没有 `i18next` / `react-intl`，只有「词典 + 插值 + 类型」。

## 为什么自己写

模板只需要三件事：

1. 按 key 取词条
2. `{n}` 占位符插值
3. 漏译时在**编译期**报错

i18next 有 40KB+ 与一整套插件生态，对这个需求过重；而类型安全用 TypeScript 就够。

## 目录

```
src/i18n/
├── index.ts          # useI18n / translate
├── modules.ts        # 导航 / 路由 / 页签标题的多语言投影
└── locales/
    ├── zh.ts         # 中文（基准，key 的定义来自这里）
    ├── en.ts         # 英文（类型 = keyof typeof zh）
    └── keys.ts       # 路径 / 模块 id → 词条 key 的索引
```

## 用法

```tsx
import { useI18n } from '@/i18n'

function Toolbar() {
  const { t, locale, setLocale, isEn } = useI18n()
  return (
    <button onClick={() => setLocale(isEn ? 'zh-CN' : 'en-US')}>
      {t('common.refresh')}
      {t('common.total', { n: 268 })} {/* → "共 268 条" / "268 total" */}
    </button>
  )
}
```

命令式场景（图表 option、toast）用不依赖 hook 的版本：

```ts
import { translate } from '@/i18n'
translate('en-US', 'dashboard.revenue') // → "Revenue (MTD)"
```

## 新增词条

1. 在 `locales/zh.ts` 加一条中文
2. 在 `locales/en.ts` 加对应英文 —— **漏了会编译报错**，因为 `en` 的类型是 `Record<keyof typeof zh, string>`

```ts
// zh.ts
'orders.batchShip': '批量发货',
// en.ts
'orders.batchShip': 'Ship selected',
```

## 导航标题怎么翻译

模块清单里写的是可读中文（`title: '用户管理'`），多语言由 `i18n/modules.ts` 统一投影：

```
优先级：节点上的 titleKey  >  locales/keys.ts 里的路径索引  >  中文 title
```

- **新模块**：在 `module.ts` 里直接写 `titleKey: 'nav.users'`
- **老模块**：只需在 `locales/keys.ts` 的 `NAV_KEY_BY_PATH` 里加一行，不用改 `module.ts`

侧边栏、页签、命令面板、面包屑读的都是投影后的结果，因此**切换语言时它们会同步刷新**，业务代码无需感知。

## 语言存在哪里

语言写在 `ui-store` 的 `locale` 字段，随 `nexus-ui-prefs` 一起持久化；
`index.html` 的内联脚本会在首帧前把它写回 `<html lang>`，避免服务端/客户端语言不一致的闪烁。

## 覆盖范围

| 区域 | 状态 |
| --- | --- |
| 侧边栏导航 / 分组 | ✅ |
| 顶栏（搜索、通知、语言、外观、头像菜单） | ✅ |
| 主题设置面板 | ✅ |
| 登录页 | ✅ |
| 页签栏（含关闭/关闭其他） | ✅ |
| 页面内部文案（表格列名、图表标题等） | ⏳ 逐步覆盖，新增页面请用 `t()` |

> 页面内部文案没有一次性全量替换，是刻意的：业务页的文案往往随业务改动，过早抽词条反而增加维护成本。
> 需要时按上面的方式加词条即可，机制已经完全就绪。
